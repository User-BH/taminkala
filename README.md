# سایت تأمین کالا باختر

> طراحی و توسعه: **شرکت رهوار پیوند داده**

سایت معرفی شرکت تأمین کالا باختر به‌همراه پیکربندی سرور برای سامانه‌های داخلی.

## نصب روی ویندوز سرور (روش اصلی)

یک فایل zip شامل همه‌چیز (پایتون، سایت، استعلام چک، بیمه و حواله)؛ روی سرور چیزی نصب نمی‌شود.

1. zip را در `C:\` باز کنید تا `C:\TaminKala` ساخته شود.
2. روی `install.bat` دوبار کلیک کنید (اجازه‌ی مدیر را بدهید). سرویس با ویندوز اجرا می‌شود، پورت‌ها در فایروال باز می‌شوند
   و اگر صفحه‌ی پیش‌فرض IIS پورت 80 را گرفته باشد، فقط همان سایت پیش‌فرض متوقف می‌شود.
3. به‌روزرسانی: بسته در شاخه‌ی `release` همین مخزن منتشر می‌شود (`TaminKala-windows.zip` + `VERSION.txt`)؛
   با `bash windows/publish.sh` یا خودکار با GitHub Actions (`.github/workflows/windows-release.yml`) در هر push روی شاخه‌ی پیش‌فرض.
   روی سرور `update.bat`: دانلود را در مرورگر (واردشده به گیت‌هاب) شروع می‌کند و در اجرای بعد zip را از Downloads نصب می‌کند.
   با یک توکن فقط‌خواندنی در `data\github-token.txt` خودش دانلود و نصب می‌کند. تنظیمات در `data\` می‌ماند.

`update.bat` به‌روزرسانی · `status.bat` وضعیت · `restart.bat` راه‌اندازی دوباره · `uninstall.bat` حذف سرویس · تنظیم پورت‌ها: `data\config.json`

ساخت بسته از روی مخزن (روی لینوکس/مک با اینترنت): `bash windows/build.sh` ← `dist/TaminKala-windows-<نسخه>.zip`
کد سرور: `windows/server.py` (Waitress؛ سایت 80، پیچک 8081، بیمه 8082؛ `/ports.json` برای لینک‌های سایت).
سامانه بیمه و حواله فقط از شبکه داخلی باز می‌شود (`bime_allow` در `data\config.json`؛ پیش‌فرض شبکه‌های خصوصی و خود سرور)؛
هم server.py بر اساس IP واقعی اتصال رد می‌کند و هم قانون فایروال `TaminKala-internal` پورت آن را فقط برای شبکه داخلی باز می‌کند.
از بیرون، کارت بیمه در سایت پنهان می‌شود و پورت آن صفحه `public/internal-only.html` (۴۰۳) را نشان می‌دهد.
روی میکروتیک فقط پورت‌های سایت و پیچک را dst-nat کنید.
پشت CDN (ابرآروان): `pichak_host` در `data\config.json` (پیش‌فرض `check.tkbp.ir` و `check.tamintabriz.ir`؛ یک نام یا فهرست) استعلام چک را روی همان پورت سایت با
تشخیص Host سرو می‌کند تا با HTTPS ابرآروان کار کند؛ پاسخ‌های `/api/` پیچک `Cache-Control: no-store` دارند تا CDN آن‌ها را کش نکند.

## ساختار روی سرور لینوکس (روش قبلی)

یک آدرس (دامنه یا IP)، هر سرویس روی پورت جداگانه:

| سرویس | پورت پیش‌فرض | محل فایل‌ها |
|---|---|---|
| سایت معرفی شرکت | `80` | `/opt/taminkala/public` (از همین مخزن) |
| سامانه پیچک (استعلام چک) | `8081` | `/opt/pichak` با venv خودش — Nginx فقط به `127.0.0.1:8088` پراکسی می‌کند |
| سامانه بیمه و حواله | `8082` | `/opt/taminkala/bime` (از همین مخزن) |

- هیچ مسیری از سایت اصلی به سامانه‌ها نمی‌رسد؛ `آدرس/pichak` یا هر آدرس ناموجود دیگر،
  صفحه **۴۰۴ با قالب تأمین کالا** را نشان می‌دهد (روی هر سه پورت).
- پیچک باید فقط روی `127.0.0.1` گوش دهد (`PICHAK_BIND=127.0.0.1:8088`) تا مستقیم از بیرون در دسترس نباشد.

## نصب و به‌روزرسانی (برای همه، بدون نیاز به دانش فنی)

### بار اول
روی سرور (اوبونتو/دبیان):
```bash
git clone https://github.com/User-BH/taminkala.git /tmp/taminkala
sudo bash /tmp/taminkala/deploy/taminkala.sh install
```
اسکریپت چند سؤال می‌پرسد (آدرس مخزن، پورت‌ها، دامنه)؛ برای قبول مقدار پیش‌فرض فقط Enter بزنید.

> **مخزن خصوصی:** بعد از خصوصی شدن مخزن، یک‌بار روی سرور اجرا کنید:
> ```bash
> sudo taminkala deploy-key
> ```
> یک کلید فقط‌خواندنی ساخته و نمایش داده می‌شود؛ آن را در GitHub → مخزن → Settings → Deploy keys → Add deploy key
> اضافه کنید (تیک Allow write access را نزنید) و Enter بزنید. اتصال از طریق پورت 443 انجام می‌شود
> (برای سرورهایی که پورت 22 آن‌ها بسته است).

### دفعات بعد
```bash
sudo taminkala            # منوی ساده
sudo taminkala update     # دریافت آخرین نسخه و اعمال آن
sudo taminkala status     # وضعیت و بررسی سلامت هر سه سرویس
sudo taminkala rollback   # برگشت به نسخه قبل از آخرین به‌روزرسانی
sudo taminkala settings   # تغییر پورت‌ها، دامنه و مسیرها
```

ویژگی‌های اسکریپت:
- قبل از اعمال، پیکربندی Nginx را تست می‌کند؛ اگر خطا داشت تنظیمات قبلی را برمی‌گرداند و سایت فعلی از کار نمی‌افتد.
- اگر روی سرور فایلی دستی تغییر کرده باشد، قبل از به‌روزرسانی از آن پشتیبان می‌گیرد (`/etc/taminkala/backups`).
- پورت‌های تکراری یا اشغال‌شده را تشخیص می‌دهد و در صورت فعال بودن `ufw` پورت‌ها را باز می‌کند.
- تنظیمات در `/etc/taminkala/taminkala.env` (بیرون از مخزن) ذخیره می‌شود و با به‌روزرسانی پاک نمی‌شود.
- سامانه پیچک (`/opt/pichak`) را تغییر نمی‌دهد.

### سامانه بیمه و حواله
فایل `bime/index.html` در همین مخزن است و با `sudo taminkala update` به سرور منتقل می‌شود.
اگر نسخه‌ای که قبلاً دستی در `/var/www/bime` کپی شده بود با نسخه مخزن فرق داشته باشد،
یک‌بار در `/etc/taminkala/backups/bime-from-server-*.html` پشتیبان گرفته می‌شود.

### OCR کپچای پیچک
پوشه `pichak-ocr/` موتور جدید تشخیص کپچا را دارد (فقط با Pillow، بدون نیاز به tesseract):
متن خاکستری کپچا از دایره‌های رنگی جدا می‌شود و هر رقم با الگوهای ساخته‌شده از کپچاهای واقعی مقایسه می‌شود.
اگر مطمئن نباشد پیشنهادی نمی‌دهد (کاربر مثل قبل دستی وارد می‌کند) تا جواب غلط پیشنهاد نشود.

```bash
sudo taminkala update               # دریافت آخرین نسخه مخزن
sudo taminkala pichak-ocr           # تست + نصب در /opt/pichak + ری‌استارت + آزمایش زنده
sudo taminkala pichak-ocr rollback  # برگشت به OCR قبلی
```
اگر سرویس بعد از نصب سالم بالا نیاید، نسخه قبلی خودکار برگردانده می‌شود.

**بهبود دقت با نمونه‌های بیشتر:** نمونه‌های جدید (از خروجی `sudo taminkala doctor`) را در
`pichak-ocr/samples/` بگذارید، پاسخ هرکدام را در `labels.json` بنویسید و اجرا کنید:
`python3 pichak-ocr/build_templates.py pichak-ocr/samples/` — گزارش دقت را نشان می‌دهد و الگوها را بازسازی می‌کند.

### عیب‌یابی پیچک
```bash
sudo taminkala doctor
```
بدون هیچ تغییری روی سرور، وضعیت پورت‌ها (از جمله 2083)، سرویس پیچک، نصب بودن tesseract و تنظیم OCR را
بررسی می‌کند و چند نمونه کپچای زنده را همراه با خروجی خام OCR در یک فایل `tar.gz` ذخیره می‌کند.

### افزودن سرویس جدید در آینده
۱. فایل‌های آن را به مخزن اضافه کنید.
۲. یک بلوک `server` با پورت جدید در `deploy/nginx/taminkala.conf.template` اضافه کنید (و در صورت نیاز متغیر پورت در `deploy/taminkala.sh`).
۳. روی سرور: `sudo taminkala update`

## سایت معرفی

سایت استاتیک و تک‌صفحه‌ای (HTML/CSS/JS خالص) در پوشه `public/`.
هم‌راستا با طراحی سامانه‌های پیچک و بیمه/حواله (رنگ قرمز `#cf1725`، گرادیان تیره–زرشکی، فونت وزیرمتن).

- **حالت روشن / تاریک**: پیش‌فرض روشن است؛ کاربر با دکمه بالای صفحه می‌تواند تاریک کند و انتخابش ذخیره می‌شود (با ریلود یا بازدید بعدی همان حالت می‌ماند).
- **واکنش‌گرا**: دسکتاپ، تبلت و موبایل.
- بخش‌ها: هیرو، آمار، سامانه‌ها، درباره ما، حوزه فعالیت (غذایی، بهداشتی، شوینده، چای و قهوه)، خدمات، فرآیند همکاری، برندها، همکاری، تماس (با نقشه نشان).

### عکس‌ها
فقط عکس‌های واقعی نمایش داده می‌شوند (جای خالی در صفحه نیست):

| فایل | محل نمایش |
|---|---|
| `public/assets/img/photos/loading.jpg` | عکس اصلی بالای صفحه (بارگیری در انبار) |
| `photos/office.webp`، `courtyard.webp`، `warehouse-overview.webp` | بخش درباره ما (ساختمان اداری، محوطه، انبار) |
| `photos/warehouse-panorama.webp` | پانورامای «زیرساخت» با حرکت هنگام اسکرول |
| `photos/office-building.webp`، `warehouse-aisles.webp`، `warehouse-variety.webp`، `building.jpg`، `warehouse-homecare.webp` | گالری (`#gallery`) با نمایش کامل در پنجره |
| `public/assets/img/brands/*.jpg` | ویترین برندها (هر نسبتی؛ بدون برش) |

بعد از افزودن یا عوض کردن هر عکس (jpg در `photos/` یا `brands/`) اجرا کنید: `python3 tools/images.py` — نسخه‌های WebP در اندازه‌های مختلف (`w/`)، لوگوهای کوچک و تصویر اشتراک‌گذاری (`og-image.jpg`) ساخته می‌شوند.

برند جدید: یک `<button class="bs-item">` با `data-cat` و `--r` (عرض/ارتفاع عکس) در بخش `#brands` فایل `public/index.html` اضافه کنید. عکس‌ها را قبل از آپلود فشرده کنید (حداکثر ~۳۰۰KB).

### سئو و سرعت
- Lighthouse (موبایل/دسکتاپ): Performance ۹۹/۱۰۰، Accessibility، Best Practices و SEO هر سه ۱۰۰.
- داده‌ی ساختاریافته‌ی JSON-LD (WholesaleStore: نشانی، تلفن، ساعات کاری، مختصات، برندها)، `robots.txt`، `sitemap.xml`، `manifest.webmanifest`، Open Graph با تصویر ۱۲۰۰×۶۳۰.
- فونت وزیرمتن روی خود سرور (`assets/fonts`، بدون وابستگی به CDN خارجی)، تصاویر WebP واکنش‌گرا، فشرده‌سازی gzip و کش در `windows/server.py`.
